# КодыОшибокКонфигурацииИнтерпретатора

Публичный модуль со стабильными кодами предметных ошибок `engine-config`. Все функции возвращают `Строку`.

## Коды

| Функция | Значение | Назначение |
| --- | --- | --- |
| `РасчетКонфигурацииНеВыполнен()` | `engine_config.calculate_failed` | Ошибка построения конфигурации из CFG и окружения |
| `ЗаписьКонфигурацииНеВыполнена()` | `engine_config.write_failed` | Ошибка проверки, записи или безопасной замены CFG |
| `ОчисткаПослеЗаписиНеВыполнена()` | `engine_config.cleanup_failed` | CFG установлен, но файл отката не удален |
| `УстановкаОкруженияНеВыполнена()` | `engine_config.environment_failed` | Ошибка формирования или установки `OSCRIPT_CONFIG` |
| `ПутьНеРазрешен()` | `engine_config.path_unresolved` | Относительный библиотечный путь невозможно разрешить |
| `НекорректнаяКонфигурация()` | `engine_config.invalid_configuration` | CFG, строка окружения или экспортируемая пара некорректны |

## Проверка ошибки

Пакет использует библиотеку `errors`: высокоуровневая ошибка сохраняет исходную причину в цепочке. Поэтому
проверяйте не только верхний код, но и всю цепочку.

```bsl
#Использовать errors

Попытка
    Конфигурация.ЗаписатьВФайл("build/oscript.cfg");
Исключение
    Ошибка = ИнформацияОбОшибке();
    Если ДиагностикаОшибок.Содержит(
        Ошибка,
        КодыОшибокКонфигурацииИнтерпретатора.ЗаписьКонфигурацииНеВыполнена()
    ) Тогда
        Сообщить("Не удалось записать конфигурацию");
    КонецЕсли;
КонецПопытки;
```

Ошибки проверки публичных аргументов используют стандартные коды библиотеки `errors`, например
`argument.invalid_type`, `argument.required` и `argument.invalid_value`.
